# Domain docs

This repository uses a single-context layout.

Before exploring the codebase:
- Read `GLOSSARY.md` at the repository root.
- Read decisions in `docs/adr/` relevant to the work.

If these files do not exist, proceed silently. Create them only
when domain-modeling work resolves terms or decisions.

Use the glossary's vocabulary in issues, code, tests, and proposals.
When a needed term is missing, reconsider the wording or record
the gap for domain modeling.

If a proposal contradicts an existing ADR, identify that conflict
explicitly instead of silently overriding the decision.
